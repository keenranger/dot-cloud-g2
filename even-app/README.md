# Even Hub cloud companion

This independent companion connects G2 directly to the hosted relay and to Soniox speech-to-text. It requires no Mac service and no customer-run server. The owner signs into the relay in ChatGPT, creates a one-time device code, then enters the relay HTTPS origin and code in this app. Only the returned device-scoped bearer token is saved through Even Hub native local storage; ChatGPT browser cookies and owner tokens are not copied to the glasses app.

## Build

```sh
pnpm install
pnpm build
pnpm test
pnpm lint
pnpm typecheck:test
RELAY_ORIGIN=https://YOUR-DEPLOYED-SITE.example pnpm manifest
```

`pnpm manifest` writes the ignored `app.json` with an explicit network whitelist origin. Copy that manifest alongside the contents of `dist/` when preparing an Even Hub package. An empty whitelist is deliberately not emitted: its host behavior has not been assumed. The exact deployed relay origin must be added before packaging and must match the origin entered on the phone. SDK version is pinned to 0.0.16 (requires Even app 2.2.10 or newer according to its package metadata). This repository does not publish or upload a package.

The relay must allow CORS for the actual hosted/packaged Even Hub WebView origin, including Authorization and Content-Type headers and OPTIONS preflights. The relay URL allowlist and backend CORS allowlist are separate settings.

## Interaction and evidence

Create the G2 startup text container before opening its microphone. Hold/release G2 LONG_PRESS_EVENT / LONG_PRESS_RELEASE_EVENT to capture up to 30 seconds; phone start/stop buttons provide the same operation. The whole reply is sent to the event-capturing G2 text container (`isEventCapture: 1`) in one `textContainerUpgrade`, without a page counter, and the G2 firmware wraps and scrolls it natively. The SDK documents a 2,000-character upgrade limit without naming the unit; the app counts JavaScript string length (UTF-16 code units), so up to 2,000 Hangul syllables stay one update. Only a longer reply is split, at a line or word break and never inside a surrogate pair, into the fewest parts, with `(계속)`/`(이어서)` markers on G2; the phone always shows the whole reply. The G2 header shows the reply position (`답변 3/7`) and microphone status. Status changes rewrite only the header, and the reply body is rewritten only when the selected message or part changes, so status updates do not move the reader back to the top. Navigation: G2 `SCROLL_TOP_EVENT`/`SCROLL_BOTTOM_EVENT` move to the adjacent part of a split reply, else to the adjacent message from its start. The SDK documents these events as swipe up/down or reaching the top/bottom boundary; whether a swipe inside overflowing text also emits them, and whether an upgrade resets the native scroll position, is not yet verified on G2. On the phone, labeled message buttons change messages and the `G2 이전/다음 부분` buttons, shown only for a split reply, change parts without leaving the message. Up to 100 deduplicated replies are retained; new batches follow the newest reply only when the reader is already at the tail, preserving an earlier reading position otherwise. A reply received before its submission HTTP response settles cannot be replaced by a stale waiting notice. When a submission notice is on G2 while an earlier message is selected, the next reply restores that message in place of the notice, and the phone says the new reply is in the following message. Audio is SDK mono PCM16 little endian at 16 kHz. The phone opens a Soniox real-time session (`wss://stt-rt.soniox.com`, `stt-rt-v5`, Korean hint) with the user's own key in the `soniox-api-key` WebSocket subprotocol when a manual recording starts, and writes each PCM frame to it as the SDK delivers it, so recognition runs while the user speaks. Frames that arrive while the socket is still connecting are copied into a bounded queue (10 seconds) and flushed in order after the start message; overflowing that queue or 10 seconds of unsent socket data fails the session with an explicit notice instead of dropping audio. Release sends end-of-audio once, waits for Soniox `finished`, and only then submits the final text. Non-final running text is shown on the phone only, marked as unconfirmed; it is never shown on G2, stored in history or submitted. The relay only receives the resulting text through `POST /api/device/utterances`. Neither the key nor audio is sent to the relay. Each recording carries one UUID from capture to submission, and a typed or reviewed draft keeps its UUID until the relay accepts it, so a resend is idempotent. Voice transcripts send automatically by default, so holding and releasing G2 completes recording, transcription, and server submission without touching the phone. The accessible automatic-send checkbox can be turned off to review the editable transcript first; typed text always uses the explicit send action. A recording submits at most once, with the connection generation checked after transcription and before sending. Ctrl/Command+Enter respects Korean IME composition.

Pairing: `POST /api/device/pair {code}` returns `{token,deviceId}`. The phone strips whitespace from the pasted 64-character hex code and lowercases it before sending. A failed new pairing (wrong or expired code, network failure or 15-second timeout) keeps the previous working connection and explains the failure next to the form. Recording is unavailable while the text field holds a typed or reviewed draft, so a transcript never replaces it, and text edited while a send is in flight stays in the field. If an automatic voice send fails or is aborted (also by unloading the app) while the connection stays the same, the transcript is left in the field, after any typed text, for an explicit resend; nothing is resent automatically. A request that gets no response is reported in Korean as cancelled by unloading the app, a 45-second timeout or a network failure, and a submission additionally says that whether the server stored it is unknown, instead of the browser's English abort text. Authenticated endpoints: `POST /api/device/utterances {id,text}`, `GET /api/device/messages` returning `{messages:[{message_id,text,createdAt,utterance_id?}]}`. The relay defines accepted as callback HTTP acceptance. It does not prove that Dot processed the message. The phone explicitly separates server storage/callback receipt from reply arrival and G2 text update acknowledgement. A successful SDK update acknowledges the update request, not independent optical verification.

Phone visibility alone does not stop a ready glasses session. Requests and capture stop on page unload, host exit or disconnect. Successful polls reconcile unacknowledged display writes without rewriting acknowledged replies. Root double-tap requests the system exit dialog; cancelling leaves the session running. Polling remains serialized at 2.5-second intervals. Disconnect clears native local credentials; revoke the paired device from the server to invalidate the token itself. G2 SDK writes are serialized and stale queued writes are invalidated on a connection change.

## Soniox key (bring your own)

The phone settings accept the user's own Soniox API key in a masked field. The key is read, then the field is cleared immediately. By default it stays in memory only and disappears when the app closes. The **remember on this device** checkbox is an explicit opt-in that writes it through Even Hub SDK `setLocalStorage` only; there is no browser storage fallback. Turning remembering off, replacing the key or clearing it overwrites the stored copy, and a storage write that cannot be confirmed is reported as such. No encryption at rest is claimed; how the Even app stores SDK values is not documented. Users should create a dedicated key in the Soniox console that only has real-time speech-to-text permission.

Without a key, the record button is disabled, G2 hold and Hey dots show a notice instead of opening the microphone, and typed text still works. A transcription is aborted when the page unloads or the host exits, the connection is disconnected or replaced, the key changes or is removed, or (for a Hey dots clip) Hey dots is turned off, and an aborted or stale transcript is never submitted. User notices come from the failure kind and at most the numeric provider code; the key and provider error text are never logged or shown. There is no automatic retry, since every Soniox session is billable.

The network whitelist contains the relay origin, `wss://stt-rt.soniox.com` and `https://stt-rt.soniox.com`, matching published Even Hub Soniox apps. `api.soniox.com` is not listed because it is unused.

## Remaining runtime checks

Build and protocol tests use fake sockets and sentinel keys only; they do not prove a real Soniox session or measure end-to-end latency, physical microphone capture, Even Hub network permissions/CORS, gesture delivery, ChatGPT event delivery, or visible G2 text. Validate these separately with a deployed relay, authorized ChatGPT MCP subscription, and connected physical G2. Locked-phone operation requires beta-build verification. Android may suspend the WebView and lose in-memory state; uninterrupted execution is not guaranteed.

## Local Hey dots activation (on by default)

The **Hey dots** checkbox is on by default and can be turned off at any time. It opens the G2 microphone only while the glasses session is active, the G2 page is ready, the phone is paired and a Soniox key is set, and no manual recording, pending transcription/submission or unsent draft competes for it; until then the phone and G2 header name the missing prerequisite, and listening starts by itself once the last one is met. Phone-local keyword spotting detects the English phrase `HEY DOTS`, then captures only the post-cue utterance. The Soniox session opens only after the cue is detected, never while waiting for it. Post-cue PCM is written to it while the utterance is still being spoken, but only once local VAD has heard speech; until then it is withheld locally, and a no-speech capture never leaves the phone. The streamed bytes are exactly the trimmed post-cue clip, excluding the cue and pre-wake audio. The local VAD endpoint then ends the session and the final text goes through the same MCP submission pipeline. Pre-cue PCM stays in the bounded local worker/ring buffers, is never sent anywhere, and is cleared on cancellation. The microphone state is visible on both the phone and a separate G2 header. Replies retain their display area when listening resumes.

This adapts the MIT-licensed Dot Link wake detector/worker/engine/name modules from local source revision `fe00d2e2c43686eca572ce5694612b505843a820`; see `public/DOT-LINK-LICENSE.txt` and the original implementation notes in `public/REFERENCE-WAKE-WORD.md`. The pinned assets are sherpa-onnx **1.13.8**, int8 Zipformer GigaSpeech 3.3M English keyword spotting, and Silero VAD. The `distribution/wake/manifest.json` preserves file sizes, SHA-256, upstream source commit and download provenance. All 11 assets were copied from already-verified local Dot Link assets without downloads. Builds and tests recheck every packaged asset. Runtime/model licenses and notices are included in `public/wake-assets/THIRD-PARTY-NOTICES.txt` and copied into `dist/`. `pnpm format` excludes the pinned runtime files so their hashes remain unchanged.

Silero uses a 1.2-second silence endpoint; no-speech capture expires at 6 seconds and clips are capped at 30 seconds. The worker queue fails closed above 48,000 pending bytes, rejects malformed/oversized PCM, and uses generation guards. Turning the option off, unloading/exiting the app, disconnecting, a manual recording, Soniox transcription/submission, a missing Soniox key, or an unsent text draft suspends local listening and closes its microphone. No wakeup after app exit or OS suspension is claimed. Manual hold/release, phone buttons and text remain available. A long press during wake capture cancels that wake clip and starts a new manual recording; releasing completes the manual clip. Empty/no-speech wake captures restore the selected reply instead of leaving the speak-now prompt. Turning wake activation off, a manual takeover, unloading, disconnecting or a key change aborts the post-cue Soniox session; nothing is written after the abort and its transcript is never submitted. The new package ID is `app.mark.evendotscloud`; availability still needs confirmation in Even Hub.

Offline real-WASM tests initialize the custom `dots` keyword and models and confirm silent input does not activate. Deterministic engine tests cover post-cue trimming, no-speech expiry, silence endpoint, maximum duration and cancellation. These are not evidence of positive `Hey dots` acoustic detection accuracy, Korean-pronunciation accuracy, physical G2 microphone behavior, or battery use; those require physical audio validation.
