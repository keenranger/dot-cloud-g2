# Even Hub cloud companion

This independent companion connects G2 directly to the hosted relay and to Soniox speech-to-text. It requires no Mac service and no customer-run server. The owner signs into the relay in ChatGPT, creates a connection key (no expiry, reusable, and shown again on the dashboard to the signed-in owner; a newer key replaces it), then enters the relay HTTPS origin and key in this app's `연결 코드` field. Only the returned device-scoped bearer token is saved through Even Hub native local storage; ChatGPT browser cookies and owner tokens are not copied to the glasses app.

## Build

```sh
pnpm install
pnpm build
pnpm test
pnpm lint
pnpm typecheck:test
RELAY_ORIGIN=https://YOUR-DEPLOYED-SITE.example pnpm manifest
```

`pnpm manifest` writes the ignored `app.json` with an explicit network whitelist origin. Copy that manifest alongside the contents of `dist/` when preparing an Even Hub package. An empty whitelist is deliberately not emitted: its host behavior has not been assumed. The exact deployed relay origin must be added before packaging and must match the origin entered on the phone. SDK version is pinned to 0.0.16 (requires Even app 2.2.10 or newer according to its package metadata). Release packaging and upload steps live in `AGENTS.md`; uploads need explicit authorization. The dated 0.3.0 Private upload is recorded there as historical evidence, not current build or phone-runtime proof.

The relay must allow CORS for the actual hosted/packaged Even Hub WebView origin, including Authorization and Content-Type headers and OPTIONS preflights. The relay URL allowlist and backend CORS allowlist are separate settings.

## Interaction and evidence

Create the G2 startup text container before opening its microphone. Hold/release G2 LONG_PRESS_EVENT / LONG_PRESS_RELEASE_EVENT to capture up to 30 seconds; phone start/stop buttons provide the same operation. The whole reply is sent to the event-capturing G2 text container (`isEventCapture: 1`) in one `textContainerUpgrade`, without a page counter, and the G2 firmware wraps and scrolls it natively. The SDK documents a 2,000-character upgrade limit without naming the unit; the app counts JavaScript string length (UTF-16 code units), so up to 2,000 Hangul syllables stay one update. Only a longer reply is split, at a line or word break and never inside a surrogate pair, into the fewest parts, with `(계속)`/`(이어서)` markers on G2; the phone always shows the whole reply. The G2 header shows the reply position (`답변 3/7`) and microphone status. Status changes rewrite only the header, and the reply body is rewritten only when the selected message or part changes, so status updates do not move the reader back to the top. Navigation: G2 `SCROLL_TOP_EVENT`/`SCROLL_BOTTOM_EVENT` move to the adjacent part of a split reply, else to the adjacent message from its start. The SDK documents these events as swipe up/down or reaching the top/bottom boundary; whether a swipe inside overflowing text also emits them, and whether an upgrade resets the native scroll position, is not yet verified on G2. When a scroll cannot move (no reply yet, or the first or last message), only the G2 header says so (`받은 답변 없음`, `첫 답변입니다`, `마지막 답변입니다`) and the body keeps its scroll position. Until the first reply or notice, the G2 body names the next setup step (checking the saved connection, pairing on the phone, entering a Soniox key, or hold to speak), whether or not Hey dots is on. A G2 double tap on the app's single (root) page asks the host for its exit confirmation with `shutDownPageContainer(1)`; one request is sent at a time, and the app's own code keeps the session running until the host reports the exit, so that a cancelled confirmation can leave the app usable. Whether the confirmation layer itself emits `FOREGROUND_EXIT_EVENT` (which would pause the session until the next `FOREGROUND_ENTER_EVENT` or G2 gesture), and when the host settles the call, is not verified. SDK 0.0.16 adds no timeout of its own: probing the bundle with a native handler that never answers left `shutDownPageContainer(1)` pending for 65 seconds with no timer scheduled, so if the host only answers after the user decides, or never answers on cancel, further double taps are ignored while that call is pending. A refused or failed request is reported on the phone and the G2 header. On the phone, labeled message buttons change messages and the `G2 이전/다음 부분` buttons, shown only for a split reply, change parts without leaving the message. Up to 100 deduplicated replies are retained; new batches follow the newest reply only when the reader is already at the tail, preserving an earlier reading position otherwise. A reply received before its submission HTTP response settles cannot be replaced by a stale waiting notice. When a submission notice is on G2 while an earlier message is selected, the next reply restores that message in place of the notice, and the phone says the new reply is in the following message. A pause discards a capture in progress, so a recording, Hey dots or transcribing notice does not come back with the page: resuming shows the selected reply again, or says the capture stopped when there is none, and a transcript kept in the text field stays there. A repeated `FOREGROUND_ENTER_EVENT` while the page is already active, including one after a gesture resumed it, changes nothing: no body rewrite, no second poll chain and no interruption of a queued Hey dots command. Audio is SDK mono PCM16 little endian at 16 kHz. The phone opens a Soniox real-time session (`wss://stt-rt.soniox.com`, `stt-rt-v5`, Korean hint) with the user's own key in the `soniox-api-key` WebSocket subprotocol when a manual recording starts, and writes each PCM frame to it as the SDK delivers it, so recognition runs while the user speaks. Frames that arrive while the socket is still connecting are copied into a bounded queue (10 seconds) and flushed in order after the start message; overflowing that queue or 10 seconds of unsent socket data fails the session with an explicit notice instead of dropping audio. Release sends end-of-audio once, waits for Soniox `finished`, and only then submits the final text. Non-final running text, for both a manual hold and Hey dots post-cue speech, is shown on the phone and in the G2 body under a one-line `실시간 인식 (미확정)` label (after release, `전사 마무리 중 · 미확정 · 아직 전송 전`); it is never stored in history or submitted. G2 shows it only while that capture's own notice holds the body: each update goes through the same serialized body write as a reply, one `textContainerUpgrade` in flight at a time, and partials that arrive before G2 acknowledges it are coalesced into one write of the newest text, with no timer or pagination. The whole running text is shown up to the 2,000-unit update limit; only beyond it the oldest part is dropped behind `…`, never inside a surrogate pair. The official display guide puts a full-screen text container at roughly 400-500 characters, and whether an upgrade keeps or resets the native scroll position is not verified, so running text longer than one screen may not show its newest words on G2. A reply received during the capture updates the phone and the history at once and is shown on G2 after the capture is submitted; moving to a message ends the G2 running text for that capture. An owner deletion or retention expiry during a capture is not such a reply: the running text stays on G2 while the phone drops the removed replies, the submission or review notice follows as usual, and a reply received during the capture but deleted before it ends does not come back. If an automatic submission is accepted after a deletion was seen, G2 and the phone both say the question may have been deleted with the conversation, never that it was not sent. A cancelled capture drops its running text and G2 falls back to the plain capture notice, and a late result from a cancelled, replaced or exited session is never shown. Running-text updates leave the phone display status at one stable `G2에 실시간 인식(미확정) 표시 중` instead of announcing each update. Display latency and legibility of running text on G2 are not measured on a device. The relay only receives the resulting text through `POST /api/device/utterances`. Neither the key nor audio is sent to the relay. Each recording carries one UUID from capture to submission, and a typed or reviewed draft keeps its UUID until the relay accepts it, so a resend is idempotent. Voice transcripts send automatically by default, so holding and releasing G2 completes recording, transcription, and server submission without touching the phone. The accessible automatic-send checkbox can be turned off to review the editable transcript first; typed text always uses the explicit send action. A recording submits at most once, with the connection generation checked after transcription and before sending. Ctrl/Command+Enter respects Korean IME composition.

Pairing: `POST /api/device/pair {code}` returns `{token,deviceId}`. The phone strips whitespace from the pasted 64-character hex code and lowercases it before sending. A failed new pairing (wrong or expired code, network failure or 15-second timeout) keeps the previous working connection and explains the failure next to the form. Recording is unavailable while the text field holds a typed or reviewed draft, so a transcript never replaces it, and text edited while a send is in flight stays in the field. If an automatic voice send fails or is aborted (also by the G2 page leaving the glasses foreground or the page unloading) while the connection stays the same, the transcript is left in the field, after any typed text, for an explicit resend; nothing is resent automatically. A request that gets no response is reported in Korean as cancelled because the G2 page left the foreground or closed (or the page unloaded), a 45-second timeout or a network failure, and a submission additionally says that whether the server stored it is unknown and that, if it was stored, the answer is not cancelled and is shown when it arrives, instead of the browser's English abort text. Cancelling here only stops this device waiting; the relay has no server-side cancellation of the model's work. Authenticated endpoints: `POST /api/device/utterances {id,text}`, `GET /api/device/messages` returning `{messages:[{message_id,text,createdAt,utterance_id?,stage?,seq?}],conversation_revision?,retention_cutoff?}`. `stage` is `ack` for the model's short reply before it works and `final` (or absent) for an answer. An acknowledgement and its final answer are two messages that both stay in the history, deduplicated by `message_id`; the final never replaces or deletes the acknowledgement text. An utterance always reads acknowledgement then final: one that arrives after its final (a capped or reordered batch) is placed just before it, and one this device already has stays when a relay no longer returns it (the 0.6.0 relay omitted an answered acknowledgement). A reader at the tail follows the newest message as for any reply; a reader elsewhere, including on the acknowledgement, keeps their place, and only the header changes. The G2 header and the phone message position name the stage: an acknowledgement is `중간 답변`, with `최종 답변 대기` until its final is kept, and a final beside its acknowledgement is `최종 답변`; a reply without an acknowledgement has no stage label. Both entries count toward the 100-reply cap and expire on their own `createdAt`, so an acknowledgement goes before its final. The existing message buttons and G2 scroll navigation read both. The acknowledgement or final for the capture being finished and submitted is shown on G2 at once, while running text of a capture that is still recording keeps the body as for any other reply. In the 0.5.0 candidate the companion reads the two optional fields as follows. A higher `conversation_revision` than the one already seen means the owner erased the conversation on the dashboard: cached replies, the reader position and the selected body are cleared on the phone and G2, a deletion notice is shown, and only that response's own messages are applied. Typed text, its draft, the Soniox key, pairing, preferences and microphone state are kept. A lower revision is a stale snapshot and the whole response is ignored; a missing revision (an older relay) is append-only. Deletion is never inferred from IDs missing in the capped batch of 100. `retention_cutoff` (UTC, now minus 30 days) prunes known replies whose `createdAt` is at or before it; a reply without a parseable timestamp is kept, and an older cutoff cannot restore a pruned reply. A 410 from `POST /api/device/utterances` (`Utterance was deleted` or `Utterance expired`) is shown explicitly and never replayed; the text stays in the field and the next deliberate send uses a new ID. A deletion is seen only on the next active poll, so while the G2 page is paused the phone page keeps its cached replies until resume. The relay defines accepted as callback HTTP acceptance. It does not prove that Dot processed the message. The phone explicitly separates server storage/callback receipt from reply arrival and G2 text update acknowledgement. A successful SDK update acknowledges the update request, not independent optical verification.

Requests are aborted when the G2 page leaves the foreground, the page unloads (`pagehide`; a back-forward-cache `pagehide` is not an unload) or the connection is removed; polling is serialized at 2.5-second intervals while the G2 page is open, and a `pageshow` resumes it. A G2 startup that completes after `pagehide` stays paused until `pageshow`. The reply body is written before the header, and a rejected or failed write of either container is left uncached, so the next successful poll retries any unacknowledged display write without rewriting an acknowledged reply. Root double-tap requests the system exit dialog; cancelling leaves the session running. Disconnect clears native local credentials; revoke the paired device from the server to invalidate the token itself. G2 SDK writes are serialized and stale queued writes are invalidated on a connection change.

## Soniox key (bring your own)

The phone settings accept the user's own Soniox API key in a masked field. The key is read, then the field is cleared immediately. By default it stays in memory only and disappears when the app closes. The **remember on this device** checkbox is an explicit opt-in that writes it through Even Hub SDK `setLocalStorage` only; there is no browser storage fallback. Turning remembering off, replacing the key or clearing it overwrites the stored copy, and a storage write that cannot be confirmed is reported as such. No encryption at rest is claimed; how the Even app stores SDK values is not documented. Users should create a dedicated key in the Soniox console that only has real-time speech-to-text permission.

Without a key, the record button is disabled, G2 hold and Hey dots show a notice instead of opening the microphone, and typed text still works. A transcription is aborted when the G2 page leaves the foreground or exits, the page unloads, the connection is disconnected or replaced, the key changes or is removed, or (for a Hey dots clip) Hey dots is turned off, and an aborted or stale transcript is never submitted. User notices come from the failure kind and at most the numeric provider code; the key and provider error text are never logged or shown. There is no automatic retry, since every Soniox session is billable.

The network whitelist contains the relay origin, `wss://stt-rt.soniox.com` and `https://stt-rt.soniox.com`, matching published Even Hub Soniox apps. `api.soniox.com` is not listed because it is unused.

## Remaining runtime checks

Build and protocol tests use fake sockets and sentinel keys only; they do not prove a real Soniox session or measure end-to-end latency, physical microphone capture, Even Hub network permissions/CORS, gesture delivery, ChatGPT event delivery, or visible G2 text. Validate these separately with a deployed relay, authorized ChatGPT MCP subscription, and connected physical G2. Phone page visibility is not tracked; only a genuine page unload (`pagehide`) pauses the session until `pageshow`. As app policy, a locked phone or a backgrounded Even app does not stop Hey dots, manual G2 capture or reply polling, and only the G2 microphone is requested (phone microphone frames are ignored); this is what the code does, not a platform guarantee that the WebView keeps running while locked. Only host events change that: `FOREGROUND_EXIT_EVENT` pauses (microphone closed, requests and transcriptions aborted), `FOREGROUND_ENTER_EVENT` or any later G2 gesture resumes, and `SYSTEM_EXIT_EVENT`/`ABNORMAL_EXIT_EVENT` clean up for good. Reading the foreground events as the G2 page leaving or returning to the glasses foreground rests on indirect evidence only: they belong to the host's PB-aligned glasses event enum and arrive on the same channel as G2 gestures, and the SDK bundle derives no event from browser visibility. Neither the SDK nor the official docs (Page Lifecycle, Background & Lifecycle, Device APIs, FAQ, glossary, changelog) define them, so whether the host ever sends `FOREGROUND_EXIT_EVENT` on a phone lock is unresolved. The phone status names every such pause and resume, so a device run shows it directly. The official Background & Lifecycle guide says the iOS WebView keeps running while backgrounded, and that Android may suspend it under memory pressure, which stops microphone capture; neither is verified on a device.

## Local Hey dots activation (on by default)

The **Hey dots** checkbox is on by default and can be turned off at any time. From 0.5.0 on, an explicit OFF/ON choice for Hey dots and for voice auto-send is saved through Even Hub SDK storage (key `dot-cloud-preferences-v1`, no browser storage). Both defaults (on) apply only when nothing was saved, and restoring never writes. Until the saved choice has been read, the microphone stays closed and both checkboxes are locked, so a saved OFF never opens the microphone during startup. If the saved value cannot be read or is malformed, both are treated as OFF and the phone says why. A failed write is reported as holding for this session only. The preference code never writes the Soniox key. Historical 0.4.2 did not save these choices; both started on at each launch there. Persistence across a full Even app relaunch is not yet verified on a device. It opens the G2 microphone only while the app's G2 page is open (the app does not pause it on a phone lock or a backgrounded Even app; whether the host keeps it running then is unverified), the G2 page is ready, the phone is paired and a Soniox key is set, and no manual recording, pending transcription/submission or unsent draft competes for it; until then the phone and G2 header name the missing prerequisite, and listening starts by itself once the last one is met. Phone-local keyword spotting detects the English phrase `HEY DOTS`, then captures only the post-cue utterance. The Soniox session opens only after the cue is detected, never while waiting for it. Post-cue PCM is written to it while the utterance is still being spoken, but only once local VAD has heard speech; until then it is withheld locally, and a no-speech capture never leaves the phone. The streamed bytes are exactly the trimmed post-cue clip, excluding the cue and pre-wake audio. The local VAD endpoint then ends the session and the final text goes through the same MCP submission pipeline. Pre-cue PCM stays in the bounded local worker/ring buffers, is never sent anywhere, and is cleared on cancellation. The microphone state is visible on both the phone and a separate G2 header. Replies retain their display area when listening resumes.

Audio reception status (0.5.0 candidate): after the SDK accepts an open request the label reads "G2 마이크 시작 요청 수락 · 오디오 수신 대기 중" (awaiting frames, not "on"); only a real G2 frame switches it to "마이크 켜짐". If no frame arrives within 4 seconds of opening, or 6 seconds after the last frame, the phone and G2 header only report "G2 오디오 수신 확인 안 됨", noting that quiet can be normal. This is observation only: nothing is closed, reopened, discarded or blocked, and a manual capture keeps recording. The SDK documents no frame cadence, so missing frames are not proof of a microphone fault. Closing still happens on user OFF, a G2 foreground exit, unload and host exit. A manual capture that never receives audio ends at the 30-second cap or on release with Soniox's distinct `no-audio` message. Whether the host withholds frames during silence, and how often the label appears on a locked iPhone, is not yet observed on a device.

This adapts the MIT-licensed Dot Link wake detector/worker/engine/name modules from local source revision `fe00d2e2c43686eca572ce5694612b505843a820`; see `public/DOT-LINK-LICENSE.txt` and the original implementation notes in `public/REFERENCE-WAKE-WORD.md`. The pinned assets are sherpa-onnx **1.13.8**, int8 Zipformer GigaSpeech 3.3M English keyword spotting, and Silero VAD. The `distribution/wake/manifest.json` preserves file sizes, SHA-256, upstream source commit and download provenance. All 11 assets were copied from already-verified local Dot Link assets without downloads. Builds and tests recheck every packaged asset. Runtime/model licenses and notices are included in `public/wake-assets/THIRD-PARTY-NOTICES.txt` and copied into `dist/`. `pnpm format` excludes the pinned runtime files so their hashes remain unchanged.

Silero uses a 1.2-second silence endpoint; no-speech capture expires at 6 seconds and clips are capped at 30 seconds. The worker queue fails closed above 48,000 pending bytes, rejects malformed/oversized PCM, and uses generation guards. Turning the option off, the G2 page leaving the foreground or exiting, the page unloading, disconnecting, a manual recording, Soniox transcription/submission, a missing Soniox key, or an unsent text draft suspends local listening and closes its microphone. No wakeup after the app exits is claimed. Manual hold/release, phone buttons and text remain available. A long press during wake capture cancels that wake clip and starts a new manual recording; releasing completes the manual clip. Empty/no-speech wake captures restore the selected reply instead of leaving the speak-now prompt. Turning wake activation off, a manual takeover, the G2 page leaving the foreground, disconnecting or a key change aborts the post-cue Soniox session; nothing is written after the abort and its transcript is never submitted. The package ID is `app.mark.evendotscloud`. Install an authorized Private build through Me > Apps > Private builds in the Even app; re-read remote build state before acting.

Offline real-WASM tests initialize the custom `dots` keyword and models and confirm silent input does not activate. Deterministic engine tests cover post-cue trimming, no-speech expiry, silence endpoint, maximum duration and cancellation. These are not evidence of positive `Hey dots` acoustic detection accuracy, Korean-pronunciation accuracy, physical G2 microphone behavior, or battery use; those require physical audio validation.

## Candidate expiry reconciliation

In 0.5.0, expiry removes an expired reply from the phone reader even while G2 shows a waiting or capture notice. The phone moves to a kept reply or the expiry notice without rewriting the G2 body, claiming a new reply arrived, changing drafts, or controlling the microphone. An older cutoff cannot restore expired text. Final local runtime scenarios passed 41/41 and companion tests 100/100; screen-reader announcements and real Even Hub/G2 behavior remain unverified.
